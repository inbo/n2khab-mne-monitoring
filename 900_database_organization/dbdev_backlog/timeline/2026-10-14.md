## update rule issue on #mnmsurfdb #FieldWork

There was an issue reported by #EDM that field forms would not correctly insert #Observations data on new activities,
except when saving the tab before every switch.

Part of the reason might be the update rules, which were previously defined as follows:

First, there is a conditional `INSERT` for novel `*Observations`.
```sql

DROP RULE IF EXISTS fieldwork_ins_POBS ON "inbound"."FieldWork";
CREATE RULE fieldwork_ins_POBS AS
ON UPDATE TO "inbound"."FieldWork"
WHERE (NEW.perturbationobservation_id IS NULL
  AND NEW.link_observation_perturbation)
DO ALSO
 INSERT INTO "inbound"."PerturbationObservations" (
  teammember_id,
  date_visit,
  location,
  visit_id,
  is_linked_to_visit,
  grts_address,
  wkb_geometry
 ) VALUES (
  NEW.teammember_id,
  NEW.datetime_visit::date,
  CAST( NEW.grts_address AS varchar),
  NEW.visit_id,
  TRUE,
  NEW.grts_address,
  NEW.wkb_geometry
 )
;

```

In a second update step, all other fields are filled.
```sql

DROP RULE IF EXISTS fieldwork_upd_POBS ON "inbound"."FieldWork";
CREATE RULE fieldwork_upd_POBS AS
ON UPDATE TO "inbound"."FieldWork"
DO ALSO
 UPDATE "inbound"."PerturbationObservations"
 SET
  notes = NEW.perturbation_notes,
  [...]
WHERE
  perturbationobservation_id = OLD.perturbationobservation_id -- !!!
  AND grts_address = OLD.grts_address
  AND visit_id = OLD.visit_id
;

```

The issue on this second line was the `OLD.*observation_id` check: 
for novel observations, that index is not set yet, and it remains `NULL` in `OLD` even for the second update.

As a fix, all fields are now added to the `INSERT` rule for novel observations.
