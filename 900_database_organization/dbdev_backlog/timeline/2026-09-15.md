## `type_assessed` should never be `'onveranderd'` #locevaldb #AquaticTypesVisits 

issue with #Visits: type_assessed was set to `onveranderd` as default, which makes no sense
+ This happened during [[structure/introduce table inheritance to locevaldb Visits for LOCEVALAQ|introduce table inheritance to locevaldb Visits for LOCEVALAQ]]
+ correction (1): set better default for `type_assessed`
	+ ```sql
	   ALTER TABLE "inbound"."Visits" ALTER COLUMN type_assessed SET DEFAULT NULL;
	   ```
+ correction (2): existing data, unvisited
	+ ```sql
	  UPDATE "inbound"."Visits"
	  SET type_assessed = NULL
	  WHERE date_visit IS NULL 
	    AND teammember_id IS NULL 
	    AND NOT visit_done 
	    AND type_assessed = 'onveranderd'
	  ;
	  -- UPDATE 588
	  ```
+ correction (3): visits were done
	+ ```
    -- SELECT DISTINCT type, grts_address, date_visit FROM "inbound"."Visits" WHERE type_assessed = 'onveranderd';
         type     | grts_address | date_visit 
    --------------+--------------+------------
     3130_aom_0_1 |       617774 | 2026-07-02
     3130_na_0_1  |     49768174 | 2026-06-30
    (2 rows)
	```
	+ those are not visible in QField; 617774 is well scheduled but for another type.
	+ Turns out that the affected 617774 activity is a SAMPLPOINT activity which should not have `type_assessed` in the first place.
	+ ```sql
	  UPDATE "inbound"."OtherVisits"
	  SET type_assessed = NULL
	  WHERE grts_address = 617774
	    AND visit_done 
	    AND type_assessed = 'onveranderd'
	  ;
	  -- UPDATE 1
	  ```
	  + The other one, 49768174, was reviewed with @WT and corrected manually.
